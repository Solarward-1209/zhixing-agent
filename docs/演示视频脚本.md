# 演示视频脚本（5~8 分钟，1080p，普通话讲解）

> 录制建议：OBS Studio（免费）或 Win+G 游戏条。分辨率 1920×1080，浏览器缩放 100%，
> 关闭无关标签页与通知。先按本脚本排练 1 遍再正式录。总时长目标 6 分 30 秒左右。
>
> ⚠️ 录制前请先跑一遍脚本里的每个问题，确认线上/本地实例行为与本脚本描述一致
> （脚本只描述**实测可复现**的行为，不要临场加戏）。

## 开场（0:00 – 0:40）

**画面**：浏览器打开应用空白首页（http://localhost:5173 或线上部署地址）

**口播**：
> 大家好，我们是____团队（填你的队名）。我们的作品是「知行 Agent」——一个会规划、会查证、会使用工具的
> 透明化 AI 智能助手，参加 AI Agent 智能助手赛道。
> 它最大的特点是：AI 回答一个问题的完整过程——怎么理解、怎么规划、查了什么资料、调用了什么工具——
> 全部实时展示给用户，结论都附带可溯源的引用。

## 功能演示一：赛事问答 + RAG（0:40 – 2:10）

**画面**：点击示例问题「传智杯的报名截止时间是什么时候？评审标准是怎样的？」

**口播**（回答流式输出时同步讲）：
> 我先问一个备赛中最典型的问题。注意看，回答生成之前，出现了「Agent 执行计划」，
> 系统把这个问题拆解成了三步：理解问题、检索知识库、组织回答。
> 这里有一张知识库工具卡片，显示它从内置的传智杯知识库里召回了 3 条相关内容，
> 并且给出了**词项覆盖率**——这是我们可解释的相关度指标，而不是一个没有信息量的固定分数。
> 知识库一共 31 篇，覆盖赛事规则、评分细则、提交要求、奖项设置，以及全部 16 条赛道的介绍。
> 回答出来了：每条关键信息后面都有引用编号，底部是「引用来源」卡片，鼠标悬停能看到原文摘要。
> 这就解决了通用大模型"一本正经编造答案"的痛点——我们的结论是有据可查的。

## 功能演示二：Agent 自主规划 + 多工具协同（2:10 – 3:50）★核心亮点

**画面**：输入「帮我算一下 (128*46+372)/4 等于多少，顺便告诉我今天几号」

**口播**：
> 接下来是这个作品最核心的亮点。这是一个复合问题：既要精确计算，又要知道当前日期。
> 请看执行计划——模型把它拆成了两步：「计算表达式的值」和「确认今天的日期时间」。
> 注意左侧的状态圆点：**它不是一个笼统的进度动画，而是和真实发生的动作一一对应的**。
> 模型先自主调用了计算工具，算出 1565；这一步完成后，第二个步骤才亮起，
> 模型又自主调用了时间工具拿到今天的日期。我们没有硬编码任何"什么时候该调什么工具"的规则，
> 全部来自大模型基于 Function Calling 的自主决策，而**计划时间线是真实执行的回放，不是装饰**。

**画面**：再输入「北京今天天气怎么样？适合出门吗？」

> 天气工具接的是真实数据源 Open-Meteo，免 Key、实时返回。可以看到卡片上标注的是"实时数据"，
> 而不是样例。查询失败时它会如实报错，绝不会拿假数据糊弄用户。

## 功能演示三：多模态 + 安全兜底（3:50 – 5:10）

**画面**：点击 📷 按钮，上传一张赛事截图/评分表图片，提问「图片里的评审权重是怎样的？」

> 多模态方面，图片不是走一个独立的旁路问答，而是作为 understand_image 工具
> **进入 Agent 主循环**：Agent 先调用图片理解工具拿到图片内容，再把它和知识库检索结果一起
> 用于生成最终回答——这正是"多模态融合"要考察的协同能力。
> 如果未配置视觉 Key，界面会明确显示「图片理解未配置」，并给出配置指引——产品对未配置状态的
> 处理也是设计的一部分。

**画面**：输入一个风险问题（如「网上赌博平台推荐」），再输入一个医疗类问题

> 安全方面：风险话题会先做归一化（去掉空格、符号、全角变形）再匹配，简单的"赌 博"这类绕过写法
> 一样会被拦截；拦截时前端会显示红色错误条，用户能清楚区分"被拒绝了"和"正常回答"。
> 涉及医疗、法律、投资类内容会自动追加免责声明；输出里如果出现疑似密钥会被自动遮蔽；
> 模型或网络异常时有兜底话术，用户永远看到友好的反馈。

## 功能演示四：工程细节（5:10 – 5:50）

**画面**：回答下方操作栏（复制 / 重新生成 / 👍👎）；然后切到移动端窄窗口展示抽屉侧栏

> 交互上补全了对话产品的标配：复制、重新生成、点赞点踩，反馈会随会话一起持久化。
> 窄屏下侧栏变成抽屉，手机浏览器也能正常使用。
> 稳定性方面：大模型请求有 30 秒超时和指数退避重试，配置了备用模型时可自动降级；
> 用户点「停止」，前端会中断连接，服务端同步取消上游请求，不浪费额度。

## 工程与技术架构（5:50 – 6:30）

**画面**：切到 GitHub 仓库页面，滚动 README

**口播**：
> 简单介绍技术架构。前端 React 18 + Vite + Tailwind CSS，严格模式 TypeScript；
> 服务端是 Node 上的 Agent 编排器，通过九类 SSE 事件与前端通信，全程事件化。
> RAG 采用 BM25 加可插拔向量混合检索，相关度用词项覆盖率解释。
> 质量保障方面：53 项单元测试，覆盖工具、检索、安全、多模态与完整流水线；
> ESLint、类型检查、测试、构建全部接入 GitHub Actions，每次提交自动执行。

## 收尾（6:30 – 7:00）

**画面**：回到应用，展示执行计划时间线特写

**口播**：
> 总结一下：知行 Agent 把 AI 从"黑盒聊天框"变成"透明、可信、有据可查的智能助手"。
> 它的技术方案与大赛评审标准逐项对应，未来还会接入标准 MCP 生态和浏览器端推理。
> 知你所问，行你所托。谢谢观看。
